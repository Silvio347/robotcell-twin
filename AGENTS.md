# Repository Guidelines

## Overview

Digital twin of the Inatel robot cell (Stäubli SCARA + Jaka Minicobo, two
conveyors, B&R Power Panel PLC). A React + TypeScript + Vite website shows the
cell live from MQTT (HiveMQ Cloud over WebSockets). The cell's Automation
Studio project lives in `plc/`.

Start with `docs/README.md` for the full picture.

## Layout

| Path | Content |
|---|---|
| `src/model/` | I/O map (`cell.ts`), robot axes (`robots.ts`), taught poses (`poses.ts`), payload parsing (`messages.ts`) |
| `src/estimator/` | Robot phase and joints estimated from PLC I/O (pure engine + task definitions + store runner) |
| `src/mqtt/` | Topics and the single broker connection (subscribe only) |
| `src/sim/demo.ts` | In-browser demo cycle |
| `src/components/`, `src/hooks/` | UI |
| `scripts/simulate.mjs` | MQTT simulator (same cycle as the demo) |
| `plc/ProjetoFinalRobotica/` | Automation Studio 4.1 project, Automation Runtime E3.10 |
| `docs/` | Project docs, MQTT contract, publishing plan |

## Commands

- `npm install`: install dependencies.
- `npm run dev`: local dev server.
- `npm run build`: type-check and production build. Must pass before every commit.
- `npm run simulate`: publish fake cell data (needs `MQTT_URL`, see README).

## Code rules

- Code, comments and docs in English.
- The website is read-only: do not add MQTT publishing from the browser
  without an explicit design for safety (PLC interlocks, confirmation).
- Never commit broker passwords or hosts. `VITE_*` variables are public;
  real values go in `.env.local`, which is ignored.
- Validate every incoming payload in `src/model/messages.ts`.
- Keep the estimator engine (`src/estimator/engine.ts`) pure: no store, no timers.
- Keep these in sync when they change:
  - `src/sim/demo.ts` and `scripts/simulate.mjs` (same cycle).
  - `src/model/cell.ts`, `IoMap.iom` and the table in `docs/mqtt-contract.md`.
  - Topics/payloads in code and `docs/mqtt-contract.md`.
  - Signal events in `src/estimator/tasks.ts` and `docs/robot-estimation.md`.
  - The "What is real and what is simulated" table in `README.md` whenever a
    value moves from simulated/estimated to real.
- Values not read from the real cell (poses, layout) must be marked as
  placeholders in code and docs.

## PLC project

- Do not change `plc/` unless asked. Changes run on lab equipment and need
  the professor/monitor OK; propose them in docs first.
- Never commit `Temp/`, `Binaries/`, `Diagnosis/`, `AS/`, `*.set` or
  `ProjetoPadrao.zip` (see `.gitignore` and `docs/plc-program.md`).
- Structured Text: keep the existing naming (`Jaka_DO7`, `Etapa`, ...).

## Git workflow

- One branch per change, from `main`: `feat/...`, `fix/...`, `docs/...`,
  `refactor/...`, `chore/...`.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):
  `type(scope): summary` in the imperative, lowercase, no trailing period.
  Types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `build`, `ci`.
  Scopes in use: `estimator`, `ui`, `mqtt`, `model`, `sim`, `plc`, `docs`.
- No authorship attribution in commits or pull requests: no `Co-authored-by`,
  `Signed-off-by` or "generated by" lines.
- Merge to `main` through a pull request. The PR description says what
  changed, why, and how it was tested.
- Remote uses the personal SSH alias: `git@github-pessoal:Silvio347/robotcell-twin.git`.
